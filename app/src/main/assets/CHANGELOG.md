## v4.22.4 | 2026-11-26 | code156
- 按新规格重做全屏翻页：**手指只要有滑动方向就翻一张，不看长短、不看速度**
- **行为变化**
  · 以前：滑动不到一半就退回原图（即使甩得很快）
  · 现在：只要朝一个方向挪过 2% 页宽（1080 屏上约 22px，与系统触摸抖动阈值同量级），松手就翻相邻一张
  · 轻点（手指不动）仍然不翻；第一张往右、最后一张往左仍然停住；并排三档的多张惯性不受影响
- **三个真根因（都在本次真机联调里钉死）**
  · **位移信号源恒为 0**：`currentPageOffsetFraction` 在回调里已被框架吸收；改用 `DragInteraction.Stop` 时冻结也是空 —— 该事件是异步投递的，收集器拿到时 fling 已起步、偏移已归零（真机连续 8 次全读到 0.0）。改为查看器自己逐帧累计手指位移
  · **符号相反**：左滑时 pager 的 velocity 是正的（+3882）、手指位移是负的（−0.185），旧规则要求两者同号 → 永不成立。新规则只看位移方向
  · **到位阈值 56dp**：`snapPositionalThreshold` 在 foundation 里是页宽比例（默认约 5.2%），小幅滑动的位移本身就小于它，框架判定「已到位」当场不滚 → 收到 0.1%
- **另修**：静止残留归零抢在 fling 启动之前执行（真机日志里 normalize 比 calc 早 2ms），会把拖动位移瞬时抹平 → 加 300ms 宽限期，并用 `collectLatest` 在新状态到来时取消
- **质量**
  · 全量单测 2195 例 / 0 失败 / 1 跳过（新增 3 条翻页判定用例）
  · 真机（iQOO V2463A / Android 16）实测：微滑 60px → 翻、慢拖 40% → 翻、反向 → 回上一张、轻点 → 不翻、末页 → 停住
  · 两条模型介绍树用例的条目快照同步到本次数据（169→176、LoRA 92→98、扩散 32→33）

## v4.22.3 | 2026-11-25 | code155
- 这一版只修一件事：**全屏单图左右翻页时，手指没滑过一半就退回原图**
- **根因（前两版都没修对的原因）**
  · 「快甩翻一页」这条分支需要两个证据：甩速够快（≥1200px/s）+ 手指确实朝该方向挪了一小段（≥3% 页宽）
  · 过去两次（v4.20.3 / v4.22.1）都从 pager 的「当前页偏移」里取那个位移量，而框架在回调之前就把它吸收成 0 了
  · v4.20.3 改成「松手瞬间 `DragInteraction.Stop` 时冻结」→ **同样失败**：Stop 事件的投递是异步的，收集器拿到时 fling 已经起步、偏移早已归零。真机日志连续 8 次全部读到 `0.0` 就是它
  · 结果：第 0 步的条件 `abs(位移) >= 0.03` 永远不成立，只剩「过半才翻」的老规则
- **修法**
  · 位移改由查看器自己的手势循环逐帧累计（手指位置差值汇总），与 pager 的消费、与协程调度时序都无关
  · 松手时除以页宽换算成「页」再交给判定函数；页宽未测得时返回 0，不会误翻
  · 判定阈值与目标页逻辑一律不动：快甩（≥1200px/s 且动了 3% 以上）→ 直接翻相邻一张；慢拖 → 仍然过半才翻
- **质量**
  · 全量单测 2192 例 / 0 失败 / 1 跳过（与 v4.22.2 基线一致）
- **待验**
  · 真机：轻扫一下（位移约 1/5 屏、甩速快）应当翻到下一张；慢慢拖到 40% 松手仍应退回原图

## v4.22.2 | 2026-11-25 | code154
- 这一版只做两处**回退式**修复：v4.22.1 为了手感新加的两个东西，实测反而造成了回弹，全部退回更接近原作者的做法
- **A1 图库网格回弹**
  · 现象：图库上下滑动老是「一滑就弹、弹完吸回来」，尤其捏合到 4 列、图不多的时候几乎每次都弹
  · 根因：v4.22.1 的 P2 批次把原作者特意加的「禁止拉伸」防护（`NoOverscrollContainer`）拆掉了，Android 12+ 的拉伸效果重新生效；网格滚不满一屏时，任何一次上滑都只能拉伸再弹回
  · 修法：把这层防护包回去，滚到端头就是顶住不动
  · 对照基线：原作者 v0.9.7 的 `GalleryScreen.kt:302` 一直有这一层
- **B1 全屏翻页回弹**
  · 现象：全屏看大图左右翻，松手后页面弹回原页；连续快速翻时几乎每次都不往前停
  · 根因（本轮假设）：v4.22.1 把吸附曲线从 tween 换成「刚度 250 的弹簧」，比框架默认（刚度 400）慢约三成；真机日志显示连续 8 次手势的目标页全部算对是「下一页」，但 pager 一次都没停过去
  · 修法：撤掉自定义吸附曲线，回框架默认。本轮**只动这一个变量**，其余四层自定义（滑行距离钳制、目标页判定、自绘越界、静止归零）一律不动，以便单独验证
  · 对照基线：原作者这一层是 `HorizontalPager` 全默认，任何参数都不传
- **质量**
  · 全量单测 2192 例 / 0 失败 / 1 跳过（与 v4.22.1 基线一致）
  · 「图库网格不许包 `NoOverscrollContainer`」那条接线断言同步反转为「必须包」，并新增一条校验组件定义本身没被改成空壳
- **待验（若仍回弹则下一版继续）**
  · 按预设顺序继续剥离：滑行距离钳制 → 目标页判定 → 自绘越界 → 静止归零

## v4.22.1 | 2026-11-24 | code153
- 这一版是**分布式修复批次**：七个已定位的问题（P1–P7）加三个新交互（N1–N3）
- **P7 图库闪退（最要紧的一条）**
  · 根因：调试日志缓冲超过 1000 条后，每次写入都要裁掉最老的几条，而「写入」与「裁剪」没放在同一把锁里。多个线程同时写就抛 `ConcurrentModificationException`，进程直接闪退
  · 复现条件：进图库正常浏览数十秒就必崩（真机两次独立复现，堆栈完全一致）

  · 松手后的吸附动画从「固定 260ms 的缓出曲线」换成**弹簧（刚度 250、临界阻尼）**
  · 为什么换：固定时长在小位移时起步慢、末段猛，观感是「卡一瞬再弹」；弹簧的加速度与位移成正比，小位移天然柔、大位移自然带惯性
  · 临界阻尼保证不过冲，不会「弹过头再回弹」
